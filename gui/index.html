Backtest & Parity Gate

Prove the strategy twice, then prove both versions agree — before any money (even paper) moves.
Step 1
Run dual backtest
research engine + Nautilus execution engine, same data
Step 2
Read the gate
4 tolerance checks below — all must PASS
Step 3 if PASS
Promote in Journal
strategy is cleared for paper trading
Step 3 if FAIL
Read trade diff
find the porting bug (warm-up? fees? timing?)

Why this exists: your research code and your execution code are two different programs. If they don't produce the same trades on the same data, one of them is wrong — and you'd only find out with real orders. This gate blocks Journal promotion and the Go-Live wizard until they reconcile. Try ⚠ Run with injected bug to see a failure and its diagnosis.

Optimize & Walk-Forward

Two questions every strategy must answer: are the parameters robust (not a lucky fluke), and did it work out-of-sample? Both computed from real backtests on your data.

Pick any runnable strategy: yours from Research stage up, plus anyone's public strategies once they reach Paper (community visibility rule). Runnable = has engine parameters — create new ones from the Strategy Lab's what-if editor ("Save as new strategy") or by copying from the Leaderboard.

Q1 — Is 252d / 10% a robust choice?

Press Compute: the platform runs the actual strategy 30 times (6 momentum lookbacks × 5 vol targets) on your real data and colors each cell by its Sharpe.

not computed yet

How to read it: a broad green plateau means many nearby parameters work — robust. A single bright cell in a sea of red means that one backtest got lucky — overfit. The frozen choice ◉ should sit on the plateau, not on a lone peak.

Q2 — Did it hold up out-of-sample?

The real equity curve, cut into ~6-month segments (after warm-up). Each segment's Sharpe is computed independently — parameters were never fitted to any of them. Consistent green = the edge persists; one lucky year = it doesn't.

Overfitting guards (the checklist behind the gate)

✓Parameter count ≤ 3 — this strategy tunes only 2
✓Chosen params on plateau, not peak — verify on the heatmap above
✓Out-of-sample segments never used for tuning — params frozen in git before this data existed
○Deflated Sharpe ratio — advanced check, see Docs & Learn reference (Bailey & López de Prado)
